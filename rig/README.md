# DRESS LAB V2 · 관절 리그

이 폴더는 17개 투명 PNG 파츠를 위한 **2D 계층형 관절 회전 엔진**이다. 본 게임의 캐릭터 이미지와 UI를 변경하지 않고 동작을 시험하기 위해 분리했다.

## 사용법

1. 일반 사이트에서는 **숨쉬는 듯한 idle이 자동 반복**된다. 몸통의 미세한 흔들림, 팔의 움직임, 주기적인 작은 탄성 반동이 포함된다.
   - https://251312-commits.github.io/dress-lab-v2/
2. **`?motions=1`**을 붙이면 큰 동작 다섯 개를 상단에 고정해서 보여주는 간편 테스트 화면이 열린다.
   - https://251312-commits.github.io/dress-lab-v2/?motions=1
   - `?motions=1&motion=showPose`로 열면 첨부 포즈 동작을 한 번 자동 재생한다.
3. **`?rig=1`**은 11개 관절 슬라이더와 상세 기능이 있는 개발 화면이다. 큰 동작 버튼은 여기서도 스크롤 영역 위에 고정된다.
   - https://251312-commits.github.io/dress-lab-v2/?rig=1
4. **숨쉬기 idle / 보잉! / 손 흔들기 / 인사하기** 버튼으로 반복·단발 동작을 시험한다.
5. **기본 자세 / 편안하게 / 수줍게 / 팔 들기 / 만세 / 기울기**로 포즈를 바꾼다. 관절 슬라이더를 직접 조절하면 자동 애니메이션은 멈춘다.
6. **보잉 강도**로 움직임 크기를 조절하고, **축 표시** 및 **원본 참고그림**으로 파츠 위치를 비교한다.
7. **정지** 또는 **기본 자세**로 움직임을 중지하고, **포즈 저장**으로 현재 회전값 JSON을 받을 수 있다.
8. 자동 움직임을 끄고 기본 자세를 확인하려면 주소에 `?idle=0`을 사용한다. `?rig=1&idle=0` 조합도 지원한다.

테스트 패널은 게임 플레이 기능이 아니다. `?rig=1`이 없으면 보이지 않는다. **idle만 일반 화면에서 자동 재생**하며 메인 화면의 4개 방·의상 미리보기 UI는 유지한다. 운영체제의 움직임 감소 설정(`prefers-reduced-motion`)에서는 자동 재생을 하지 않는다.

## 큰 동작 — 업로드된 포즈 기반 (2026-11-22)

사용자가 관절 테스트 화면에서 저장한 **`dress-lab-pose.json`의 11개 각도**를 [`rig/poses/user-reference.json`](poses/user-reference.json)에 **수정 없이 저장**했다. `motion.js`의 `reference` 기본 포즈와 `showPose` 동작에서 이 각도를 그대로 사용한다.

- **첨부 포즈**: 11개 관절을 업로드된 수치로 지정하는 고정 포즈. 몸통 -6°, 오른쪽 팔꿈치 +72°, 왼쪽 무릎 +37°를 포함한다.
- **첨부 포즈 연기 (`showPose`)**: 반동을 준 뒤 첨부 포즈를 크게 취하고 잠시 유지했다가 기본 자세로 돌아간다.
- **큰 손짓 (`bigWave`)**: 한쪽 팔을 들어 팔꿈치·손목을 크게 흔들고, 몸과 한쪽 다리가 함께 반응한다.
- **한발 콩콩 (`hop`)**: 한쪽 무릎을 크게 굽히고 두 번 뛰며 착지할 때 눌렸다 복원된다.
- **좌우 율동 (`dance`)**: 팔을 번갈아 흔들고 고관절·무릎을 함께 움직이며 좌우로 스텝을 밟는다.
- **기지개 (`stretch`)**: 양팔을 크게 펴며 위로 늘어났다가 천천히 내려온다.

모든 큰 동작은 **일회성**이며 끝나면 기존 숨쉬기 idle로 복귀한다. 평상시 idle이 갑자기 큰 동작을 하지 않도록 자동 재생에는 포함하지 않는다. 개발용 테스트 주소 `?motions=1`의 **고정된 큰 동작 버튼**이나 `?rig=1`의 관절 테스트 패널에서 실행하거나, 추후 게임 이벤트에서 `window.dressLabMotion.play('showPose')`처럼 호출하면 된다.

동작 키프레임은 `rig/motion.js`의 `LARGE_ACTIONS`에 기록되어 있다. 각도는 리그의 관절 제한 안에서 적용된다. 큰 동작에서 팔다리의 접합부가 벌어질 수 있으므로 시각적 보정은 향후 필요하다.

## 관절 데이터

`rig.json`에는 다음이 기록된다.

- 기준 캔버스: **1206 × 2622px**, 원점 왼쪽 위
- 회전축: `base/Full.PNG` 파란 원 **11개 중심**
- 관절별 부모 관절, 기본 0° 자세, 최소·최대 회전 각도
- 각 파츠가 따르는 관절 ID

축 좌표는 참고 이미지의 파란색 원 테두리 픽셀을 분석하고 원형 최소제곱 피팅으로 구했다. **소수 첫째 자리까지 반올림한 근삿값**이므로 실제 회전 중 경계가 어긋난다면 `rig.json`의 해당 `x`, `y` 값을 수정하면 된다.

| 축 ID | 중심 좌표 (px) | 연결된 상위 축 |
|---|---|---|
| torso | 328.6, 1166.5 | 없음 |
| shoulderL | 244.3, 1013.2 | torso |
| elbowL | 188.8, 1175.2 | shoulderL |
| wristL | 141.1, 1319.3 | elbowL |
| shoulderR | 412.8, 1013.3 | torso |
| elbowR | 468.6, 1175.2 | shoulderR |
| wristR | 516.4, 1319.2 | elbowR |
| hipL | 257.2, 1367.8 | 없음 |
| kneeL | 246.3, 1623.2 | hipL |
| hipR | 399.4, 1367.7 | 없음 |
| kneeR | 411.0, 1623.2 | hipR |

- **L은 화면 왼쪽**, **R은 화면 오른쪽** 파츠를 뜻한다.
- 머리와 목에는 별도의 회전축이 없다. 두 파츠는 몸통 움직임을 따르지만 개별적으로 돌리지 않는다.
- `Full.PNG`는 일반 렌더링의 파츠가 아니며, 테스트에서 참고 이미지를 선택할 때만 표시한다.
- 파츠 앞뒤 순서는 기존대로 파일명 숫자가 큰 것부터 그리고, **작은 번호가 위에** 온다.
- 0° 자세에서는 모든 이미지를 기존과 같이 `(0,0)`에 그대로 그리므로 원본을 왜곡하지 않는다.

## 코드 구조

- `rig.json`: 축 좌표, 부모-자식 관계, 각도 제한, 파츠별 연결
- `rig.js`: 계층형 2D 회전 렌더러. 원본 PNG의 투명 여백을 한 번 잘라서 반복 렌더링 비용을 줄이며 원래 좌표를 유지한다.
- `motion.js`: 관절별 탄성 보간, 숨쉬기 idle, 간헐적 미니 보잉, 단발 보잉·손 흔들기·인사, 고정 포즈.
- `debug.js`: 테스트 패널, 6개 기본 포즈와 동작 버튼, 강도 슬라이더, 포즈 JSON 다운로드.
- `../index.html`: 캐릭터 이미지 로딩과 렌더러 연결. 리그 로딩 실패 시 기존 정적 합성으로 돌아간다.

## 국소 신체 변형: 머리·목·상체·허리·골반·다리

- **실제 마법룸 UI:** https://251312-commits.github.io/dress-lab-v2/?room=magic&v=hip70-tabs
- **독립 개발용 패널:** https://251312-commits.github.io/dress-lab-v2/?body=1&v=magic-room-neckfix
- 원본 PNG 17개를 보존한다. 머리·목·몸통·다리 11개를 변형하고, 위팔·아래팔 4개는 길이·두께를 조정한다. 양손 2개는 손목 좌표와 함께 위치만 옮긴다. 초기화하면 원본 이미지와 관절 좌표로 복귀한다.
- **머리 크기(70~113%)**: `01-Head.PNG`를 균일 배율로 확대·축소한다. 머리 중심 X와 목 상단·어깨 높이에서 추정한 턱·목 연결 Y를 기준점으로 사용한다.
- **목 두께(80~120%)**: 실제 목 파츠의 중앙 X축을 중심으로 가로만 조절한다. 목 길이 변경과 동시에 적용할 수 있으며, 기존 상체 겹침 부분의 Y좌표를 유지한다.
- **목 길이(78~127%)**: 목 PNG의 실제 y≈895~978px와 상체 PNG의 시작 y≈961px을 비교한 뒤, **하단 겹침 부분의 y≈970px을 고정점**으로 사용한다. 기존 어깨 회전축 y≈1013px을 늘이기 기준으로 사용한 오류를 수정했다. 목 아래 약 8px은 움직이지 않고 노출된 윗부분만 세로로 변하며, 머리도 같은 거리만큼 이동한다. 머리·목 크기 조절을 조합할 수 있다.
- **팔 두께(80~125%)·팔 길이(85~120%)**: `12/13-UpperArm`과 `14/15-LowerArm` PNG를 각 뼈대(어깨→팔꿈치·팔꿈치→손목) 방향에 정렬한 아핀 변환으로 크기 변경. 길이 증감은 두 마디에 동일하게 적용하며 팔꿈치·손목의 X/Y 회전축을 재계산한다. `16-hand(L)`·`17-Hand(R)`는 형태를 유지하면서 새 손목에 따라 이동한다. 평상시 100%에서는 본래 PNG를 그대로 사용한다.
- **상체 폭(90~118%)**: `03-Bust`·`04-UpperTorso` 변형, 양팔과 상위 관절의 좌우 위치 연동.
- **허리(85~120%)**: `06-TorsoJoint`와 위·아래 토르소 경계 배율 공유.
- **골반(90~120%)**: `05-LowerTorso` 하단·`07-Hips`와 고관절·무릎·다리 위치 연동. **실제 윤곽 검토 결과** `07-Hips.PNG`와 양쪽 `UpperLeg`의 바깥선은 약 y=1330px에서 겹친다. 따라서 골반 파츠가 연결부의 공통 배율에 도달하는 구간을 y=1280~1330px로 수정했다(기존에는 회전축의 y≈1368px을 끝점으로 사용).
- **허벅지(85~135%)·종아리(85~115%)**: 골반–허벅지의 공통 연결 배율은 **`골반 배율 × [1 + 0.70 × (허벅지 배율 − 1)]`**이다. 골반 PNG와 허벅지 PNG에 같은 배율을 사용하고, 고관절·무릎 X 좌표 및 다리 이미지의 좌우 위치도 공통 연결 배율을 따라갔다. 무릎은 기존과 동일하게 `1 + 0.30 × (허벅지 배율 − 1) + 0.30 × (종아리 배율 − 1)`을 사용한다.
- **예시**: 골반100%·허벅지135% → 연결부124.5%; 골반120%·허벅지135% → 연결부149.4%. 배율 연산은 매번 원본 좌표에서 계산하며 조절을 반복해도 누적되지 않는다.
- **관절 관계**: 머리·목에 독립 회전축을 추가하지 않고 몸통 회전을 따라간다. 팔 길이가 바뀌면 어깨·팔꿈치·손목의 부모·자식 관계는 그대로 두면서 팔꿈치와 손목의 X/Y 좌표를 변경한다. 기존 idle·보잉·큰 동작은 같은 리그를 사용한다.

머리·목 기준점은 실제 PNG의 비투명 픽셀 범위와 상체 겹침을 기반으로 계산한다. 목 하단을 고정해도 큰 크기 변경 시 그림자의 경계·외곽선은 미세 조정이 필요할 수 있다. **마법룸 UI**는 `ui/magic-room.js`가 본 엔진을 호출한다. 마법룸 옆 탭은 `체형 → 피부톤 → 얼굴` 순서이고, 체형 탭에는 10개 조절 항목을 넣었다. 현재 피부톤·얼굴 탭은 안내 화면만 제공한다. 의상 변형도 아직 연결되지 않았다.

## 현재 범위와 한계

**구현됨:** 관절 11개와 파츠 17개의 연결, 독립/상속 회전, 기본 자세 복원, 각도 제한, 자동 idle, 미세 호흡·흔들림, 통통 튀는 보잉 애니메이션, 손 흔들기·인사하기, 6개 포즈(중립 포함), 움직임 감소 대응, 화면 비활성 시 일시정지.

**미구현:** 관절 틈새를 자연스럽게 메우는 메시 변형, 키프레임 편집기, 게임 대화·케어 이벤트와 애니메이션 연결, 신체를 따라 움직이는 의상 레이어 시스템.

**탄성 효과:** 관절 회전은 스프링 감쇠식으로 연결하며, 캐릭터 전체에 작은 수직 이동과 약 1% 내외의 압축·신장을 적용한다. **개별 PNG를 임의로 늘이거나 비틀지는 않는다.** 리그는 초당 최대 약 30회 갱신하며, 투명 영역을 제거한 스프라이트로 모바일의 그리기 부담을 낮춘다.

회전만으로는 팔꿈치나 무릎의 외곽선이 벌어지거나 겹쳐 보일 수 있다. 이 경우 관절용 덮개 파츠, 움직임 각도 제한, 의상 레이어의 추가 리깅 등으로 보완해야 한다. **이미지 자체를 늘려 왜곡하는 기존 V1 방식으로 돌아가지 않는다.**
