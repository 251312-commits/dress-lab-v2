# 의상 PNG 제작·전달 규칙 v1

확정일: 2026-11-24 · 대상: Dress Lab V2

이 문서는 앞으로 의상을 그려 전달할 때 사용할 프로젝트 규칙이다. **원화 PNG, 변형 영역 PNG, 연결 가이드, 짧은 메모**를 한 묶음으로 만든다. 작가는 수치 가중치나 JSON을 작성하지 않는다.

> 현재 게임에는 반팔의 몸통·양쪽 소매를 처리하는 로더가 있다. 아래 규격은 긴팔·치마·바지까지 포함하는 제작 계약이며, 색상 가이드를 자동으로 읽는 기능이나 모든 의상 종류가 이미 구현됐다는 뜻은 아니다. 신규 의상을 연결할 때 이 가이드에 맞춰 변형과 앞뒤 순서를 구현한다.

## 1. 무엇을 나누고, 무엇을 색칠하는가

- **따로 회전하는 관절을 지나면 PNG를 나눈다.** 긴소매는 팔꿈치에서 위팔·아래팔로 나눈다. 양쪽 팔도 각각 별도 파일이다.
- **체형에 반응하는 정도만 다르면 영역색으로 나눈다.** 치마 본체의 윗부분·중간·자락은 한 PNG 안에 유지하고, 영역 이미지에서 초록·노랑·파랑으로 표시한다.
- **앞뒤 순서나 독립적인 장식 처리가 필요할 때만 파츠를 추가한다.** 몸 뒤로 가는 망토, 앞에 달린 리본, 크기를 지킬 버클 등이다.

같은 옷의 재봉선마다 파일을 나누지는 않는다. 한 장으로 만든 긴소매를 단순 회전시키는 방식도 사용하지 않는다.

## 2. 모든 이미지의 공통 형식

| 항목 | 확정 규칙 |
|---|---|
| 캔버스 | **1206 × 2622px** |
| 좌표 | 제공한 기본 인형과 같은 위치. 왼쪽 위가 (0,0) |
| 기본 자세 | 모든 체형 값 100, 모든 관절 각도 0인 제공 기준 이미지 |
| 파일 | 정지 PNG, RGB 각 8bit + 알파 8bit의 RGBA, sRGB |
| 배경 | 원화·영역 이미지는 투명. 흰 배경이나 체크무늬를 그림에 구워 넣지 않는다 |
| 내보내기 | 캔버스 전체를 내보낸다. 자동 자르기, 중앙 정렬, 크기 변경 금지 |
| 좌우 | **화면 기준**. 화면 왼쪽이 `L`, 화면 오른쪽이 `R` |
| 해상도 표기 | DPI보다 위의 픽셀 크기를 기준으로 한다 |

인형은 캔버스의 왼쪽 영역에 놓여 있다. 인형 중심 x≈328.6을 캔버스 중심 x=603으로 옮기지 않는다. 비어 보이는 오른쪽 여백도 유지한다. 내부 로딩에서 여백을 줄일 때 원래 좌표를 함께 기록한다.

실제 원화의 외곽선과 반투명 효과는 정상적인 안티앨리어싱을 사용해도 된다. 원화에는 베이스 피부, 관절점, 영역색, 설명 글씨를 합치지 않는다. 옷 사이로 피부가 보일 곳은 피부색을 칠하는 대신 투명하게 비운다.

## 3. 제출 묶음: 네 종류

의상 하나를 폴더 하나에 넣어 ZIP으로 보낸다. 폴더 이름은 `white-shirt-01`처럼 영문 소문자·숫자·하이픈을 사용한다.

| 위치 | 내용 | 수량 |
|---|---|---:|
| `art/<파트명>.png` | 실제 게임에 보일 그림 | 파츠마다 1장 |
| `zones/<파트명>.zones.png` | 같은 파츠의 변형 영역 지도 | 원화마다 1장 |
| `attachment-guide.png` | 인형에 입힌 전체 모습 + 빨간 연결 표식 + 필요한 설명 | 의상마다 1장 |
| `notes.txt` | 이름·종류·기본 규칙과 다른 예외 | 의상마다 1개 |

원화와 영역 이미지는 크기·위치가 정확히 같아야 한다. 예를 들어 `art/sleeve_upper_L.png`에는 `zones/sleeve_upper_L.zones.png`가 대응한다. `.zones`는 별도 파일이며 원화에 합치지 않는다.

`attachment-guide.png`에는 참고용 인형과 설명 글씨가 들어가도 되고, 가독성을 위한 흰 배경도 허용한다. 이 파일은 게임에 표시하지 않는다. 전체 의상을 입힌 미리보기를 겸하므로 별도의 `preview.png`는 필수가 아니다. 사용한 관절의 빨간 십자와 파츠 이름을 남기고, 필요하지 않은 기준점은 지운다.

작업용 레이어 파일은 선택 사항이다. 전달에 필요한 PNG들은 반드시 함께 넣는다.

## 4. 영역색은 세 가지, 연결 표식은 따로

| 표시 | 정확한 색 | 의미 | 예시 |
|---|---|---|---|
| 초록 | `#22C55E` | 해당 파츠의 기본 규칙에 따라 체형에 맞춰 변형 | 몸통, 소매 중간, 허리띠 |
| 파랑 | `#3B82F6` | 체형 변경 때 해당 영역의 국소적인 크기·모양 보존 | 어깨의 연결 덮개, 치마 하단, 리본·단추 |
| 노랑 | `#FACC15` | 초록의 변형을 파랑의 보존 상태로 점진적으로 연결 | 어깨 아래 연결 구간, 치마 중간 |
| 빨간 십자·선 | `#EF4444` | 어디에 붙이는지 보여 주는 연결점·연결선 | 어깨, 팔꿈치, 허리 부착선 |

**초록·파랑·노랑은 `zones/`에, 빨간 표식은 `attachment-guide.png`에만 넣는다.** 빨강은 네 번째 변형 영역이 아니다. 영역색으로 앞뒤 순서도 표현하지 않는다.

### 영역 이미지 그리는 방법

1. 대응하는 원화의 실루엣을 같은 위치에 복사한다.
2. 옷이 있는 부분을 세 색 중 하나로 채운다. 가려지는 겹침 부분도 포함한다.
3. 바깥은 투명하게 두고, 색 안에는 그림자·무늬·글씨를 넣지 않는다.
4. 단단한 브러시 또는 선택 영역 채우기를 사용한다. 색은 불투명 100%로 칠하고, 색 사이를 흐리게 섞지 않는다.
5. 실제로 서서히 변형할 구간을 **단색 노랑 띠**로 표시한다. 노랑은 50% 배율이라는 뜻이 아니다.

외곽의 투명도 안티앨리어싱은 허용하지만 RGB 색은 지정한 세 색 중 하나를 유지한다. 원화가 전부 초록 규칙을 따르는 파츠라면 영역 이미지도 실루엣 전체를 초록으로 칠하면 된다.

노랑 띠는 이웃한 초록과 파랑을 연결하도록 그린다. 좁은 선 하나로 두지 않는다. 소매 연결부는 대략 위팔 길이의 1/3~1/2, 치마 중간은 허리 아래에서 자락이 안정되기까지 충분한 높이를 준다. 폭과 모양은 옷의 디자인에 맞춰 조정하고 실제 동작에서 확인한다.

### ‘고정’의 의미

파란 부분도 **연결 위치의 이동, 관절 회전, 인형 전체 움직임, 화면 확대**는 따른다. 체형 슬라이더 때문에 그림 자체가 같이 늘어나지 않도록 보존한다는 뜻이다.

빨간 표식은 연결 관계를 나타낸다. 예를 들어 빨간 허리선은 허리가 넓어질 때 양 끝이 벌어질 수 있다. 빨간색을 ‘크기까지 절대 고정’이라는 뜻으로 사용하지 않는다.

## 5. 파츠 종류별 기본 변형

색상만으로는 늘어나는 방향을 알 수 없으므로 아래 규칙을 기본값으로 적용한다. 기본값과 다를 때만 `notes.txt`에 적는다.

| 파츠 | 기본 동작 |
|---|---|
| `torso` | 가슴·허리·하복부의 위치별 외곽선에 맞춘다 |
| `sleeve_upper_L/R` | 어깨 연결 덮개를 보존하고, 아래로 갈수록 팔 길이·굵기 반영을 높인다. 길이는 팔축, 굵기는 그 수직 방향이다 |
| `sleeve_lower_L/R` | 팔꿈치에서 손목까지 아래팔을 따라 길이·굵기를 바꾼다. 팔꿈치 연결점은 양쪽 파츠가 공유한다 |
| `waist_band` | **허리 폭은 따라가고 띠의 높이는 보존**한다. 기본 영역색은 초록이다 |
| `skirt` | 위쪽은 허리·상부 골반을 따라가고, 노랑에서 영향을 줄여 파란 하단의 폭·실루엣과 치마 길이를 보존한다 |
| `pelvis` | 바지의 허리·밑위·골반 외곽선을 따른다 |
| `leg_upper_L/R` | 해당 허벅지의 폭·길이와 고관절 움직임을 따른다 |
| `leg_lower_L/R` | 해당 종아리의 폭·길이와 무릎 움직임을 따른다 |
| `cuff_L/R` — 긴팔 손목 커프스를 분리한 경우 | 팔에 맞는 폭은 따라가고 커프스 높이는 보존한다. 손 회전이 아니라 아래팔을 따른다 |
| `decor_*` | 붙어 있는 위치는 따라가되 장식 자체의 크기·비율을 보존한다. 기본 영역색은 파랑이다 |

`waist_band`와 `cuff`의 ‘높이 보존’은 해당 파츠의 로컬 축 기준이다. 초록이 언제나 가로세로 일괄 확대를 뜻하지는 않는다.

### 소매는 통째로 파랑으로 칠하지 않는다

팔이 굵어지고 길어지면 소매도 그에 맞춰야 한다. 일반 소매는 **어깨 연결 덮개 파랑 → 연결 구간 노랑 → 나머지 초록**이다. 아래팔 소매는 기본적으로 초록이다. 팔꿈치 표식은 빨강으로 표시하지만, 굵기까지 고정된 작은 섬으로 만들지는 않는다.

꼭 맞는 소매 끝도 폭은 팔을 따라가야 한다. 소매 끝을 전부 파랑으로 칠해 둘레까지 고정하지 않는다. 높이를 유지할 긴팔 손목 커프스가 중요하면 `cuff_L/R`로 분리한다. 반팔 끝의 띠를 따로 그릴 때는 `cuff_upper_L/R`로 이름을 붙여 해당 위팔을 따르게 한다. 두 종류 모두 폭 추종·높이 보존이며, 무늬만 보존할 때는 무늬를 `decor_*`로 분리한다.

소매 길이만 그대로 두고 폭은 팔을 따르게 하고 싶다면 초록 영역을 유지하고 `notes.txt`에 **‘소매: 길이 보존 / 폭 추종’**이라고 적는다. 한 방향만 보존하는 예외를 새로운 색으로 만들지는 않는다.

### 치마자락은 따로 잘라내지 않는다

치마는 기본적으로 **허리 연결부 `waist_band` + 본체 `skirt` 두 장**이다. 본체 안에서 위쪽 초록 → 중간 노랑 → 하단 파랑으로 표시한다. 밑단을 파란색이라는 이유만으로 또 잘라내지 않는다. 좌우 다리를 따라 두 갈래로 나누지도 않는다.

허리가 이동하면 치마 전체도 함께 이동한다. 기본값은 **허리에서 밑단까지의 길이와 파란 하단 폭을 유지**하는 것이다. 바닥에 닿는 세계 좌표를 유지하는 규칙과는 다르다. 바닥 길이 유지가 필요한 옷은 예외로 명시한다.

파란 하단이 최대 체형의 골반·허벅지를 덮기에는 좁으면 ‘모양 보존’과 ‘몸을 덮기’를 동시에 만족할 수 없다. 본체 상부의 초록·노랑을 넉넉하게 잡고 최대 체형에서 확인한다. 타이트한 치마처럼 하단도 몸에 맞아야 하는 디자인은 해당 부분을 초록으로 표시한다. 모든 치마에 파란 자락을 강제하지 않는다.

## 6. 의상별 기본 파츠 수와 이름

아래 숫자는 **원화 PNG만 센 개수**다. 영역 PNG와 전체 가이드는 별도이다.

| 의상 | 기본 개수 | 파일 이름 |
|---|---:|---|
| 민소매 상의 | 1 | `torso.png` |
| 반팔 상의 | 3 | `torso.png`, `sleeve_upper_L.png`, `sleeve_upper_R.png` |
| 긴팔 상의 | 5 | 반팔의 3장 + `sleeve_lower_L.png`, `sleeve_lower_R.png` |
| 치마 | 2 | `waist_band.png`, `skirt.png` |
| 민소매 원피스 | 2 | `torso.png`, `skirt.png` |
| 반팔 원피스 | 4 | `torso.png`, `skirt.png`, 좌우 위팔 소매 |
| 긴팔 원피스 | 6 | 반팔 원피스 4장 + 좌우 아래팔 소매 |
| 반바지 | 3 | `pelvis.png`, `leg_upper_L.png`, `leg_upper_R.png` |
| 긴바지 | 5 | 반바지 3장 + `leg_lower_L.png`, `leg_lower_R.png` |
| 장갑 한 쌍 | 2 | `glove_L.png`, `glove_R.png` |

원피스에서 눈에 보이는 허리띠가 독립적으로 필요한 경우에만 `waist_band.png` 한 장을 추가한다. 겉옷의 뒤판이 몸 뒤로 지나가면 `back_panel.png`, 독립 장식은 `decor_bow.png`처럼 역할을 드러내는 이름으로 추가한다. 단순한 재봉선이나 색 차이만으로 기본 개수를 늘리지 않는다.

### 긴팔의 분할 위치

- 위팔 소매: 어깨에서 팔꿈치까지. 소매 끝이 팔꿈치보다 위에 있으면 아래팔 파일은 만들지 않는다.
- 아래팔 소매: 팔꿈치에서 손목까지.
- 손목에서 옷을 자르는 기본 긴팔은 손 그림을 포함하지 않는다.
- 긴소매 전체를 좌우 한 장씩 만드는 방식은 기본 규칙에서 제외한다. 한 장으로 팔꿈치를 접으려면 별도의 다중 관절 변형이 필요하기 때문이다.

## 7. 절단선과 겹침

관절에서 딱 맞닿도록 자르면 회전할 때 틈이 생긴다. **보이지 않는 여유까지 그려 두 파츠를 겹친다.**

- 팔꿈치에서는 각 파츠가 관절 중심을 지나 **24px씩 더 이어지게** 그리는 것을 시작 기준으로 한다. 양쪽을 합치면 중립 자세에서 약 48px의 겹침 구간이 된다.
- 어깨 뿌리는 몸통 안쪽까지, 손목 커프스는 아래팔과 겹치게 그린다. 숨겨질 끝은 둥글고 충분히 넓게 만든다.
- 잘려서 가려질 안쪽 끝에 검은 외곽선을 그리지 않는다. 겹침 부분까지 원단 색·명암·영역색을 채운다.
- 24px은 모든 옷과 자세에서 틈이 없음을 보장하는 수치가 아니다. 옷 폭과 회전 각도에 맞춰 늘리고, 실제 지원 동작에서 확인한다.
- 소매 끝·치마 밑단처럼 실제로 보이는 끝에는 정상적인 외곽선과 마감선을 그린다.

## 8. 연결 가이드와 앞뒤 순서

`attachment-guide.png`에는 기준 인형 위에 전체 옷을 합성하고, 사용한 관절 중심을 빨간 십자로 표시한다. 치마·원피스는 원하는 허리 부착선을 빨간 선으로 표시한다. 선 옆에는 파츠 이름 또는 ‘허리선’ 정도만 쓴다.

표준 허리 부착선은 기준 인형의 허리, **y≈1166.5** 부근이다. 하이웨이스트·로우웨이스트라면 실제로 원하는 선을 표시한다. 고관절 중심 y≈1368은 허리선이 아니다.

기본 합성 의도는 다음과 같다. 별도 지정이 없으면 이 의도로 연결한다.

- 몸통이 위팔 소매의 숨겨진 뿌리를 덮는다.
- 위팔 소매와 아래팔 소매는 팔꿈치의 숨겨진 여유로 이어진다.
- 손과 노출된 팔은 의상 앞에서 보이도록 한다.
- 치마 앞판은 다리 앞, 별도의 뒤판은 다리 뒤에 놓는다.
- 버클·리본 같은 장식은 붙는 원단 앞에 놓는다.

앞뒤가 특별한 옷만 `notes.txt`에 예외를 쓴다. 예: ‘리본은 오른팔 앞’, ‘망토는 몸과 팔 뒤’, ‘왼쪽 끈은 손 앞’. 색상 지도에 새로운 색을 추가해 앞뒤를 표시하지 않는다.

### 기준 관절 좌표 — 화면 좌우

| 위치 | L | R |
|---|---|---|
| 어깨 | (244.3, 1013.2) | (412.8, 1013.3) |
| 팔꿈치 | (188.8, 1175.2) | (468.6, 1175.2) |
| 손목 | (141.1, 1319.3) | (516.4, 1319.2) |
| 고관절 | (257.2, 1367.8) | (399.4, 1367.7) |
| 무릎 | (246.3, 1623.2) | (411.0, 1623.2) |

몸통 관절은 (328.6, 1166.5)이다. 치마의 허리 표식은 제작 기준선이며, 현재 리그에 `waist`나 `pelvis`라는 중앙 관절이 이미 있다는 뜻은 아니다. 장갑은 손목을 따라가지만 셔츠의 커프스는 아래팔을 따른다.

```text
규격: dress-lab-clothing-png/v1
의상 ID: white-shirt-01
의상 이름: 흰색 긴팔 셔츠
종류: long-sleeve

기본 변형: v1 기본값
앞뒤 순서: v1 기본값

```

예외가 있을 때만 마지막 항목을 구체적으로 바꾼다. 예: ‘허리띠 높이 유지, 리본 크기 유지’, ‘치마 길이는 유지하되 밑단 폭은 골반에 맞춰 늘어남’, ‘허리 부착선은 가이드의 낮은 선’.

## 10. 보내기 전 확인

1. 모든 원화·영역 PNG가 1206×2622인가?
2. 기준 인형과 겹쳤을 때 위치가 맞고, 화면 L/R이 올바른가?
3. 원화에는 피부·가이드·글씨가 섞이지 않았는가?
4. 모든 원화에 같은 이름의 `.zones.png`가 있는가?
5. 영역색은 세 색만 사용했고, 빨간 표식은 전체 가이드로 분리했는가?
6. 긴소매는 팔꿈치에서 나누고, 숨겨질 겹침을 그렸는가?
7. 파란 부분의 ‘크기 보존’과 빨간 표식의 ‘연결 위치’를 혼동하지 않았는가?
8. 전체 착용 가이드와 이름·종류·예외 메모를 넣었는가?

동작 검사는 가져오는 쪽에서 기본값, 팔 길이·굵기 최소/최대, 가슴·허리·골반·체형 비율 변화, 대기와 팔 동작을 확인한다. 그림의 의도와 계산이 충돌하면 영역·여유·지원 형태 중 무엇을 바꿀지 이 가이드를 기준으로 판단한다.

## 12. 구현 연결 메모

현재 기준 코드: [리그 좌표](https://github.com/251312-commits/dress-lab-v2/blob/main/rig/rig.json), [체형 변형](https://github.com/251312-commits/dress-lab-v2/blob/main/rig/body-shape.js), [의상 로더](https://github.com/251312-commits/dress-lab-v2/blob/main/clothes/wardrobe.js), [렌더 순서](https://github.com/251312-commits/dress-lab-v2/blob/main/rig/rig.js).

현재 로더는 정확히 세 파츠와 `torso`, `shoulderL`, `shoulderR`만 받는다. 이미지 형식으로 PNG를 읽을 수 있다는 것과 여러 종류의 의상을 가져올 수 있다는 것은 다르다. 이 문서의 가이드는 변형 의도를 전달하며, 아직 실행용 가중치 마스크나 기존 `item.json`을 대체하지 않는다.

향후 연결 시 파일 이름의 역할·영역 지도·빨간 연결선·예외 메모를 함께 해석한다. 원화 좌표를 보존한 자르기, 역할별 관절과 변형 축, 연속적인 전환, 부착물의 앞뒤 순서를 별도로 구현해야 한다. 특히 치마의 보존 하단에 현재의 전체 세로 비율 확대를 그대로 적용하면 이 규칙을 어기게 된다.

## 참고

캔버스 크기·좌표는 프로젝트의 `rig.json`에서 가져왔다. 파츠 수, 파일 이름, 세 영역색, 24px의 시작 여유는 이 프로젝트를 위해 정한 제작 규칙이며 PNG 표준의 요구사항이 아니다.

- [W3C PNG 규격](https://www.w3.org/TR/png-3/): 무손실 저장·알파 채널.
- [Spine 공식 문서: Weights](https://en.esotericsoftware.com/spine-weights): 연결과 변형 가중치의 개념 참고.
- [Spine 공식 문서: Slots](https://en.esotericsoftware.com/spine-slots): 부착 관절과 그리는 순서를 분리하는 개념 참고. 이 프로젝트가 Spine을 사용한다는 뜻은 아니다.
